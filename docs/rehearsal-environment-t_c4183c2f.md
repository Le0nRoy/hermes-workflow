## Рекомендация

Использовать уже находящийся в этом репозитории синтетический стенд `experiments/process-comparison/`: `fixture.py` (HTTP API заказов) + `ui.html` (автономный UI заказа). Это лучший подтверждённый кандидат для репетиции: исходники доступны локально, есть общий предмет (заказы), контролируемые ошибки `api-zero`, `api-bool`, `api-duplicate`, `ui-value`, `ui-double`, известный контракт и автономные проверяющие `verify.py` / `verify_ui.py`. Никаких реальных заказов, клиентских данных, учётных записей, сети вне loopback и внешнего deploy не требуется. Использовать их как учебный продукт, а не выдавать за фриланс-кейс реального клиента или за подготовленный публичный сервис.

Стенд создан для **сравнения процессов**, не для неизменяемого приёмочного эталона заказа. Для репетиции владелец и оценщик должны отдельно утвердить scope, способ передачи контролей (авторские проверки не отдавать исполнителю), правила изменений продукта и версию baseline. `t_f354669a` занимается оценкой/согласованием; этот документ не утверждает её решений. Исходная `t_9aa2074e` остаётся планом без разрешения на автозапуск; её статус не менялся.

## Предлагаемый безопасный режим после решения владельца

1. Создать отдельную копию **только** нужных открытых fixture-файлов без секретов и авторских контролей для исполнителя; проверяющему — отдельно сохранённые `verify.py` / `verify_ui.py`. Зафиксировать явный исходный commit после разрешения на первый commit или честно пометить его отсутствие, плюс хэши и версии зависимостей. Не выдавать текущие untracked файлы за стабильный commit.
2. Каждый прогон: отдельный HTTP server на `127.0.0.1:0`, свежий словарь заказов, завершение `shutdown`/`server_close` и join потока; для UI — новый browser context и локальный `file://` документ без внешних разрешений, с закрытием контекста. Имена/количества синтетические. Не запускать этот стенд на адресе `0.0.0.0`, не добавлять публичные маршруты и persistent credentials.
3. В текущем shared same-UID контуре безопасная *организационная* граница — работа только с разрешёнными файлами и запрет недоверенного кода/секретов. Если нужна настоящая техническая изоляция, согласовать отдельный низкопривилегированный UID/VM либо контейнер без host Docker socket, host mounts и credentials, с ограничением сети/ресурсов; её эффективность проверить canary-пробами. Не считать «запущено в Docker» гарантией при доступном rootful socket.
4. Утвердить квоты/маршрут модели без нового платного fallback; до конца октября 2026 ориентироваться на имеющиеся подписки Claude/ChatGPT. Не запускать методологические LLM-прогоны автоматически. Роль независимого проверяющего, публикацию ветки/PR и восстановление после сбоя оговорить явно: прежний runner Tortuga не переносится автоматически.
