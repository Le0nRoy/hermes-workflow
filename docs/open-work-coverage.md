# Покрытие открытых и отложенных вопросов карточками

Проверено 2026-10-17 по просьбе владельца текущего Desktop-чата. Область — открытые/отложенные вопросы этого обсуждения и первый спринт, не исчерпывающий аудит всех проектов пользователя. Доска `hermes-workflow`, проект `hermes` (`p_5118b7e2`); binding проверен штатным CLI.

## Метод и результаты

- Штатным `hermes kanban --board hermes-workflow list --json --archived` получен полный снимок: 64 уникальные карточки, затем `show --json` по каждому ID с описанием/комментариями/историей. Рабочие сырые снимки находятся только в scratch, не в репозитории.
- После сопоставления scope добавлены 8 карточек: четыре задачи спринта, одна `[acceptance]`, три отложенные задачи. Итоговый снимок: 72 уникальных ID, ровно 8 новых, старые статусы не изменились.
- Все новые карточки созданы атомарно `blocked`, `dir` workspace проекта, local-only; они не были запущены. Точные read-back подтверждают bodies/parents/workspace/статусы; проверены восемь dependency edges.
- Содержательные дополнения в пять существующих карточек прочитаны обратно: `t_d939d3e8`, `t_ff21a011`, `t_95b161ac`, `t_9a7b057b`, `t_2569a694`.
- Это проверка полноты планирования, не выполнения будущих acceptance criteria.

## Что не утверждается этим аудитом

Старый backlog имеет todo/triage и автоматически обрабатываемые состояния; его парковка текстом не обеспечена. Старые статусы/назначения/config не менялись. Новые карточки припаркованы безопасно, но это не разрешает claim/dispatch старых, повторную выдачу бюджетов или live вмешательство. Спринт сформирован к утверждению, не запущен. Любые последующие новые улучшения вне scope остаются сначала предложением в чате по действующей политике Б.
